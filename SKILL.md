# react-video — ролик из веб-страницы

Ролик собирается как веб-страница: React (Vite) или чистый HTML с canvas, CSS и three.js. Страница умеет нарисовать любой момент времени — `window.render(t)`. Скрипт открывает её в headless Chromium, снимает кадр за кадром и отдаёт в ffmpeg. Музыку и эффекты синтезирует другой скрипт по той же сетке времени, что и картинку. Ни облачных рендеров, ни платных фреймворков: Playwright, ffmpeg, numpy.

Рядом с этим файлом:
- `${CLAUDE_SKILL_DIR}/scripts/` — рендер, проверки, звук, сборка выдачи (у каждого скрипта есть `--help`);
- `${CLAUDE_SKILL_DIR}/templates/html/` и `${CLAUDE_SKILL_DIR}/templates/react/` — рабочие шаблоны-демо;
- `${CLAUDE_SKILL_DIR}/reference/` — подробности по темам; читать, когда дошёл до шага.

## 0. Окружение — один раз

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/check_env.py --gl
```

Скрипт проверит Python-модули, Chromium для Playwright, ffmpeg с нужными фильтрами и WebGL. На каждую проблему печатает команду установки: `pip install -r ${CLAUDE_SKILL_DIR}/requirements.txt`, `python3 -m playwright install chromium`, ffmpeg из пакетного менеджера.

## 1. Раскадровка → «ок» пользователя → только потом рендер и озвучка

Рендер и озвучка — самые дорогие шаги: минуты машинного времени и деньги за TTS. Поэтому сначала согласуй, что будет в кадре.

- Покажи пользователю таблицу по сценам: секунды, текст на экране (заголовок и подпись), слова диктора, что в кадре. Плюс одна картинка со всеми сценами: стоп-кадры черновой сцены (`render.py stills`) и лист кадров (`sheet.py`).
- В каждой сцене полной фразой: что это и что это даёт зрителю. Ролик должен читаться без звука.
- Смысл важнее хронометража. Суть не влезает в 20 секунд — предложи ролик длиннее или меньше сцен, но не режь смысл в лозунги. Из практики: промо на 22 секунды отклонили («смысл потерялся»), принят вариант около минуты.
- Цифра в кадре — только из проверенного источника (сайт, отчёт, данные пользователя) и с пояснением на экране, к чему она относится. Не выдумывай и не округляй «для красоты».
- Ролик-презентация компании: заголовки и подписи — про услуги и выгоды заказчика, а не про приёмы анимации. «Motion Design» — это то, как ролик сделан, а не то, о чём он.
- Контраст: светлое на тёмном или тёмное на светлом, ничего «чёрным на чёрном». Цветной логотип с тёмными деталями — на светлый фон. Подпись поверх пёстрой картинки — на тёмной подложке.
- Творческие законы: крючок в первые 2 секунды; показывай саму вещь — настоящие экраны продукта, фото работ, — а не абстракцию; каждый кадр должен годиться в обложку.

Жанры и их правила — промо с диктором, шоурил под музыку, версия другой длины под голос → `reference/genres.md`.

## 2. Сцена

Скопируй шаблон в папку проекта. Внутри папки скилла не работай: её перезапишет обновление.

```bash
cp -r ${CLAUDE_SKILL_DIR}/templates/html ./video    # без сборки: canvas, DOM, CSS, three.js
cp -r ${CLAUDE_SKILL_DIR}/templates/react ./video   # React + Vite, рендер из dist/
```

Контракт страницы. Подробно, с форматом `timeline.json`, → `reference/contract.md`.
- `window.render(t, gt)` рисует момент `t` в секундах. **Каждый кадр — чистая функция времени**: никаких `Date.now()`, часов `requestAnimationFrame` и `Math.random()`, случайность — через `hash`/`rng` с зерном. `gt` — время выходного кадра. При перекарте времени оно отличается от `t`, им сидируют зерно.
- `window.T` — таймлайн из `timeline.json` (минимум `end`). `window.sceneReady = true` — после загрузки шрифтов, картинок и 3D.
- CSS-анимации и библиотеки со своими часами ставь на паузу и перематывай на `t`: `document.getAnimations()` → `pause()`, `currentTime = t * 1000`. В React кадр рисуй через `flushSync`, чтобы DOM обновился до снимка.
- `timeline.json` — единственный источник времени для картинки и звука: сцены, секции музыки, звуковые события (`cues`). Сдвинул событие — перезапусти генерацию звука.

Правила кадра:
- Вертикаль для Reels, Shorts и Telegram — 1080×1920, 30 к/с. Безопасная зона — y 220…1500, x ≤ 940: справа кнопки, снизу подпись. В неё должен попадать и свой текст, и ключевые цифры внутри скриншотов. Проверяй скриптом, а не на глаз:
  ```bash
  python3 ${CLAUDE_SKILL_DIR}/scripts/layout_check.py --dir video
  ```
  Проверяются элементы с атрибутом `data-check`, чтение — по `data-read`, текст на canvas — через хук `window.layoutBoxes(t)`.
- Чтение: не больше 3,5 слова в секунду на сцену. Тот же `layout_check.py` считает это до рендера.
- Показывай настоящие экраны и компоненты продукта. Рамка-акцент — на то, о чём говорит заголовок, а не на самый заметный блок.
- Типографика: «ёлочки», неразрывные пробелы после коротких предлогов, перед ₽ и внутри чисел.
- Шрифты — woff2 (кириллица и латиница) в папке проекта со своим `fonts.css`. Перед первым кадром — `document.fonts.load("900 100px 'Unbounded'", 'АБВГД…')`: вторым аргументом кириллица, иначе подтянется только латиница.
- Ассеты «с сайта» (карта, логотип, фото) — те, что видит посетитель на живой странице, а не файл с подходящим именем в `img/`. Найди блок на странице и посмотри, откуда он берёт картинку. Файл, на который ничто не ссылается, скорее всего устарел.
- 3D без видеокарты, контурный текст без линий внутри букв, SVG из CorelDRAW, что тормозит при программной отрисовке → `reference/scene-techniques.md`.

## 3. Рендер

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/render.py stills 0.5,2.6,4.0 --dir video
python3 ${CLAUDE_SKILL_DIR}/scripts/render.py video raw.mp4 --dir video --blur 6 --poster 3.7
```

Для React сначала `npm install` и `npm run build` в папке шаблона, потом `--dir video/dist`.

- Размытие движения — главный признак «студийной» картинки. `--blur N` снимает N подкадров в пределах затвора 180° и усредняет их. Для выдачи N = 4–6, для черновиков 1. Середины переходов смотри со смазом: `render.py stills … --blur 4`.
- `--poster T` заменяет кадр 0 кадром момента `T`, это обложка в ленте. Кадр заменяется, а не добавляется.
- Один браузер за раз. При `--blur 6` 2D-сцена занимает около 1,6 с на кадр, 3D через SwiftShader — около 3,8 с. 20 секунд такого ролика — порядка 20 минут и до 2,5 ГБ памяти.
- Во время рендера файлы сцены не правь: правка попадёт в оставшиеся кадры. Сначала останови рендер.
- Мелкая правка после рендера не требует рендера целиком:
  ```bash
  python3 ${CLAUDE_SKILL_DIR}/scripts/render.py video part.mp4 --dir video --from 4.0 --to 5.5 --blur 6
  python3 ${CLAUDE_SKILL_DIR}/scripts/splice.py raw.mp4 fixed.mp4 part.mp4:4.0:5.5
  ```
  `splice.py` вставляет кусок, перекодирует видео один раз и сверяет число кадров. Если правка задела почти все сцены, проще отрендерить заново.
- Версия другой длины без перерисовки сцен (например, чтобы диктор успел назвать каждую услугу): `remap.py` + `render.py --remap` → `reference/genres.md`.

## 4. Звук

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/audio_bed.py --timeline video/timeline.json --out mix.wav --stems stems
```

- Музыка — синтез по сетке и `cues` из `timeline.json`: барабаны, бас, пэд и эффекты hit, boom, whoosh, riser, tick, click, swell. Или трек с подтверждённой лицензией. Чужую музыку без лицензии не бери.
- Сетка — это темп. При 120 BPM доля — 0,5 с (15 кадров), такт — 2 с. Склейки и главные события ставь на доли, текстовые «удары» — по слову на долю. Перед главным ударом — тишина музыки (секция `gap`).
- Голос из платного TTS: сначала образцы одной фразы, потом выбор пользователя, и только потом полный прогон. Фразы встают на своё время, музыка под голосом приседает, мастер собирается в `vo_mix.py plan.json` → `reference/audio-voice.md`.
- Итог — −14 LUFS, true peak не выше −1 dBTP. AAC добавляет к пику до +0,5 дБ, поэтому `finalize.sh` ставит лимитер на −2 dBFS прямо перед кодером.

## 5. Проверка и сдача

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/finalize.sh raw.mp4 mix.wav out/promo
python3 ${CLAUDE_SKILL_DIR}/scripts/sheet.py out/sheet.jpg --video out/promo.mp4 --timeline video/timeline.json
```

`finalize.sh` собирает `out/promo.mp4`, лёгкую копию `out/promo_light.mp4`, постер `out/promo.jpg` и печатает замеры: длительность, кодеки, громкость, пик.

- Стоп-кадры каждой сцены и середины переходов посмотри сам.
- Потом — рецензент-придира: отдельный субагент смотрит лист кадров и нарезку и отвечает на вопрос «что зритель без звука поймёт из каждой сцены». Его вердикт нужен ДО показа пользователю. Свой просмотр его не заменяет: ты проверяешь композицию и контраст, а не смысл. Если отдаёшь раньше — так и скажи: «черновик, идёт вычитка». Задание придире и чек-лист → `reference/review.md`.
- Выдача: оригинал; лёгкая копия не больше 6 Мбит/с — для мессенджеров, бот Telegram принимает файлы до 50 МБ; постер, вшитый кадром 0; лист кадров; черновик подписи к посту.
- Публикация наружу — только с явного согласия пользователя.
